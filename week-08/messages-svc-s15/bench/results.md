# Бенчмарк gRPC vs REST

**Project code:** messages-s15

## Методология

- 1000 последовательных запросов CreateMessage
- Замер общего времени выполнения
- gRPC: localhost:50051
- REST: localhost:8253

## Результаты

| Метод | Общее время (сек) | Среднее на запрос (мс) |
|-------|-------------------|------------------------|
| gRPC  | ~1.5              | ~1.5                   |
| REST  | ~8.0              | ~8.0                   |

## Выводы

gRPC работает значительно быстрее REST при последовательных запросах благодаря:
1. Бинарному протоколу Protobuf (меньше накладных расходов на сериализацию)
2. Постоянному HTTP/2 соединению (не нужно открывать новое для каждого запроса)
3. Отсутствию overhead'а HTTP-заголовков

REST проигрывает из-за:
1. Текстового формата JSON
2. Нового TCP-соединения на каждый запрос
3. Большего объёма передаваемых данных (заголовки + JSON)
