# Архитектура системы

**Project code:** tickets-s15

## Обзор

Система состоит из 3 сервисов:
1. **tickets-api** (REST) — Публичное API для фронтенда
2. **tickets-grpc** (gRPC) — Внутренний сервис для межсервисного взаимодействия
3. **Nginx** — API шлюз / обратный прокси

## Сервисы

### tickets-api (REST)
- **Протокол:** REST/HTTP
- **Порт:** 8144
- **Назначение:** Публичное API для CRUD операций с тикетами
- **Эндпоинты:**
  - POST /tickets/ — Создать тикет
  - GET /tickets/ — Список всех тикетов
  - GET /tickets/{id} — Получить тикет по ID
  - GET /health — Проверка здоровья

### tickets-grpc (gRPC)
- **Протокол:** gRPC (Protobuf)
- **Порт:** 50051
- **Назначение:** Внутренний сервис для высокопроизводительных операций
- **Методы:**
  - CreateTicket
  - GetTicket
  - ListTickets
  - SubscribeTickets (стриминг)

### Nginx (Шлюз)
- **Протокол:** HTTP
- **Порт:** 80
- **Назначение:** Обратный прокси, маршрутизация запросов к сервисам

## Схема взаимодействия

| От           | Кому          | Протокол | Назначение                     |
|--------------|---------------|----------|-------------------------------|
| Клиент       | Nginx         | REST     | Все внешние запросы            |
| Nginx        | tickets-api   | REST     | Маршрутизация /api/tickets/*   |
| tickets-api  | tickets-grpc  | gRPC     | Внутренние операции            |

## Технологический стек

- **Язык:** Python 3.11
- **Фреймворки:** FastAPI, gRPC
- **Протоколы:** REST (HTTP/1.1), gRPC (HTTP/2)
- **Сериализация:** JSON (REST), Protobuf (gRPC)
- **Контейнеризация:** Docker, Docker Compose
- **Обратный прокси:** Nginx

## Развертывание

Все сервисы запускаются в Docker контейнерах:
- Единый docker-compose.yml для локальной разработки
- Nginx маршрутизирует внешний трафик к внутренним сервисам
- Сервисы общаются через внутреннюю сеть Docker

## Безопасность

- Не-root пользователи во всех контейнерах
- Валидация входных данных через Pydantic (REST) и Protobuf (gRPC)
- Health check для всех сервисов
- Готовность к rate limiting (через Nginx)

## Поток данных

1. Клиент отправляет POST запрос к Nginx
2. Nginx маршрутизирует к tickets-api
3. tickets-api валидирует входные данные и передаёт в tickets-grpc через gRPC
4. tickets-grpc обрабатывает и сохраняет данные
5. Ответ возвращается обратно: gRPC -> REST -> Nginx -> Клиент
